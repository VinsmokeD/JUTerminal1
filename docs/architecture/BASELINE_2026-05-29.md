## 3. Backend test suite

- Tests are **not** baked into the production backend image (`/app` has `src`, `migrations`, no `tests`), and `tests/conftest.py` pins `POSTGRES_URL`/`REDIS_URL` to `127.0.0.1` for host runs. DB ports are published to `127.0.0.1`, so the correct way to run the suite is a **host venv** (or a dedicated test service), not `exec` in the prod container.
- Baseline run: host `.venv` (Python 3.12.10) + `pip install -r requirements.txt` + `pytest --ignore=tests/e2e`.

**RESULT (corrected creds, live dev DB/Redis): `286 passed, 10 failed, 1 error in 9.93s`.**

- **First run with conftest defaults: 296 errors** — `asyncpg InvalidPasswordError` (wrong password, see C4). After exporting `TEST_POSTGRES_URL=...cybersim:cybersim...` the suite ran.
- **All 10 failures + 1 error are the SAME class: asyncio event-loop scope errors** — `RuntimeError: Event loop is closed` and `Future ... attached to a different loop`, raised inside CPython `asyncio/base_events.py` / `streams.py` (not in CyberSim code). Affected: `integration_test.py` (kali ref, session-persist x2, start-session), `test_output_patterns.py` (insight/cooldown x3), `test_coverage_gaps.py` (notes round-trip, sc02 insight), `test_debrief_coach.py` (fallback), `unit_test_scenarios.py::test_30`.
- **Diagnosis:** `pytest-asyncio==0.23.7` + the session-scoped autouse `init_services` fixture (opens Redis/asyncpg on one loop) clashes with per-test `[asyncio]` loops **on Python 3.12**. The project targets **Python 3.11**, where these pass (consistent with the historical "295 passing"). **Not a product bug.**
- **RESOLVED (same day, commit follows this one):** root cause was `pyproject.toml` already setting `asyncio_default_test_loop_scope = "session"` — a key **not supported by the pinned `pytest-asyncio==0.23.7`** (silently ignored → function-scoped test loops vs the session-scoped service fixture). Bumped `pytest-asyncio` to `1.4.0` (honors the existing config) and fixed the conftest password default (C4). **Suite now: `296 passed in 8.48s` on Python 3.12.** Remaining Phase 10 work: CI on the pinned interpreter + a timezone-aware JWT fix (python-jose `utcnow()` deprecation warning surfaced).

(e2e suite `tests/e2e/` is `@pytest.mark.e2e` and needs the live SC-02 stack; tracked separately in Phase 10.)
